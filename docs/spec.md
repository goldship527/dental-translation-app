# Dental Lecture Translator 仕様書

最終更新: 2026-06-02

## 1. アプリ概要

Dental Lecture Translator は、日本語の音声または日本語原稿を入力し、日本語原文、英語翻訳、簡体中国語翻訳を表示する歯科講演向け翻訳補助PWAである。

主な用途は、日本人歯科医師、歯科企業講師、インプラント関連製品担当者、海外学会・セミナー登壇者、海外ドクターと会話する日本人スタッフの翻訳補助である。

将来的には、Keynoteで録画された日本語講演動画を取り込み、英語ナレーション付き動画として書き出す講演動画ローカライズ機能へ拡張する。入力はMac上で扱う録画済みMP4を想定し、最終成果物は英語ナレーション入りMP4、英語字幕、日本語文字起こし、英訳原稿、要確認リストをまとめた配布用パッケージとする。

本アプリは医療判断、診断、治療方針決定を目的としない。専門用語、数値、術式、禁忌、適応、左右、上下顎などは必ず使用者が確認できるUIにする。

## 4. 環境変数

`.env.local` に利用するAPIキーを設定する。

```env
# Gemini
GEMINI_API_KEY=...
GEMINI_AUDIO_MODEL=gemini-2.5-flash
GEMINI_TRANSLATION_MODEL=gemini-2.5-flash
GEMINI_TTS_MODEL=gemini-3.1-flash-tts-preview

# OpenAI
OPENAI_API_KEY=sk-...
OPENAI_TRANSCRIBE_MODEL=gpt-4o-mini-transcribe
OPENAI_TRANSLATION_MODEL=gpt-4.1-mini
OPENAI_TTS_MODEL=gpt-4o-mini-tts
```

どちらか一方だけでも動作する。画面上部のAPIセレクトで Gemini / OpenAI を切り替える。

## 6. モード仕様

### 講演モード

海外講演、学会発表、セミナー説明向け。

- 長めの日本語を自然な講演文に整える
- 歯科専門家向けの表現を使う
- 口語すぎる表現を避ける
- 教育調、講演調を優先する
- 専門用語、数値、術式、製品名は保持する

### Q&Aモード

質疑応答やその場の会話向け。

- 短く簡潔
- 口頭で返しやすい
- 専門用語は崩さない
- 回答として使いやすい文体にする

### 原稿モード

事前準備用。

- 日本語原稿を貼り付けて翻訳
- スライド原稿や講演前準備を想定
- 将来的にスライド番号、テンプレート、修正版保存へ拡張する

## 7. 翻訳スタイル

選択肢:

- 専門家向け・講演調
- 丁寧なビジネス調
- 短く簡潔

## 8. API切り替え仕様

### Gemini

使用箇所:

- 音声文字起こし
- 英語・簡体中国語翻訳

特徴:

- 音声はWAVとしてinline dataで送信
- 翻訳はJSON structured outputを指定
- `503 high demand` が出ることがあるため、一度だけ短い自動リトライを行う

### OpenAI

使用箇所:

- 音声文字起こし
- 英語・簡体中国語翻訳

特徴:

- 音声文字起こしは Speech-to-Text API
- 翻訳は Responses API + JSON schema
- 課金上限、利用上限、APIキーエラーを日本語表示する

## 8.1 音声出力仕様

英語翻訳と簡体中国語翻訳に対して、手動の読み上げ機能を提供する。

実装済み機能:

- Englishカードの再生 / 停止
- 简体中文カードの再生 / 停止
- 音声タイプ選択
  - Standard
  - Calm
  - Lecture
- 読み上げ速度
  - 0.8x
  - 1.0x
  - 1.2x
- 同じテキスト、API、言語、音声タイプ、速度の組み合わせはブラウザ側で音声URLをキャッシュする
- 翻訳完了後の自動読み上げは行わない

OpenAI TTS:

- `OPENAI_TTS_MODEL` を使用
- 既定値は `gpt-4o-mini-tts`
- 音声形式は `mp3`
- speedパラメータを使用

Gemini TTS:

- `GEMINI_TTS_MODEL` を使用
- 既定値は `gemini-3.1-flash-tts-preview`
- Gemini TTSはPreview扱い
- 返却されたPCM音声をサーバー側でWAVにラップしてブラウザ再生する

注意:

- 読み上げ音声はAIにより生成された音声であることをUI上の注意文言に明記する
- 講演中の事故防止のため、現段階では自動再生は実装しない

## 9. 音声録音仕様

録音は `navigator.mediaDevices.getUserMedia` と Web Audio API で行う。

処理フロー:

1. 必要に応じて入力マイクを選択する
2. 録音開始ボタン押下
3. `マイク確認中` を表示
4. マイク権限を確認
5. 選択した入力マイクを `deviceId` 指定で開く
6. 録音中表示へ切り替え
7. 音声をFloat32Arrayとして蓄積し、入力レベルを画面に表示する
8. 日本語録音では5秒ごとに音声を区切り、無音でない区切りを文字起こしAPIへ送って録音中プレビューへ追加する
9. 録音停止時に残りの音声区切りも処理する
10. プレビューで取得できた日本語文字起こしを日本語原稿欄へまとめる
11. プレビューで文字起こしが取れなかった場合は、従来どおり録音全体をWAVへ変換して文字起こしする
12. 無音判定
13. APIへ送信

入力マイク選択:

- `navigator.mediaDevices.enumerateDevices()` で利用可能な `audioinput` を取得する
- DJI Mic Miniなどの外部マイクが認識されている場合、入力マイク欄から選択できる
- マイク権限が未許可の状態では、ブラウザ仕様によりデバイス名が「マイク 1」のように表示される場合がある
- デバイス変更時はマイク一覧を自動更新し、手動の再読み込みもできる
- 録音中は peak / RMS に基づく入力レベルを表示し、外部マイクから音が届いているか確認できる

録音中プレビュー:

- 日本語録音中は5秒ごとに録音音声を区切り、文字起こし結果を録音停止前に表示する
- 完全な同時字幕ではなく、数秒遅れで区切り単位の文字起こしを追加する疑似リアルタイム方式とする
- 無音または短すぎる区切りはAPIへ送らない
- 録音停止時には未処理の残り区切りも文字起こしし、取得済みテキストを日本語原稿欄へ反映して翻訳へ進める
- 音声区切りとプレビューはブラウザ内の一時状態として扱い、サーバー保存しない

## 10. 無音・誤認識対策

何も話していない録音をAI APIへ送ると、モデルがそれらしい講演文を補完することがある。そのため、クライアント側で以下を判定する。

- 録音時間
- ピーク音量
- RMS音量
- 発話らしい音の割合

閾値は環境変数で調整できる。未設定時は以下の既定値を使う。

```env
NEXT_PUBLIC_SILENCE_MIN_DURATION=0.6
NEXT_PUBLIC_SILENCE_PEAK=0.025
NEXT_PUBLIC_SILENCE_RMS=0.006
NEXT_PUBLIC_SILENCE_SPEECH_RATIO=0.01
```

スマホブラウザ側で参照するため、変数名には `NEXT_PUBLIC_` プレフィックスを付ける。

無音または短すぎる録音の場合はAPIへ送信せず、以下を表示する。

```text
音声が検出されませんでした。録音開始後に少し話してから停止してください。
```

APIプロンプト側にも、無音・ノイズのみの場合は空文字を返し、内容を作らないよう指示する。

## 12. 歯科用語辞書

辞書はコード内に固定せず、外部JSONとして管理する。

ファイル:

```text
public/data/dental-glossary.json
```

形式:

```json
{
  "id": "implant_001",
  "ja": "インプラント",
  "en": "dental implant",
  "zh": "牙种植体",
  "category": "implant",
  "risk": false,
  "note": "文脈によりimplantでも可"
}
```

拡張方針:

- JSON追加だけで用語拡張可能
- `category` で分類
- 主なカテゴリーは `implant`, `surgery`, `bone`, `sinus`, `soft`, `prosthetics`, `occlusion`, `anatomy`, `complication`, `maintenance`, `digital`, `manufacturer`, `implant_system`, `implant_surface`, `connection`
- メーカー名・製品システム名は原則として翻訳せず、固有名詞を保持する
- `risk: true` を要確認表示対象にする
- `note` で翻訳注意を管理
- 将来的に管理画面を追加可能な構造にする

## 12.1 翻訳履歴

翻訳が成功した結果は、端末内のlocalStorageに直近20件まで保存する。

起動時は前回の翻訳結果を自動復元せず、日本語入力欄と翻訳結果は空欄で開始する。過去の結果を使う場合は、利用者が翻訳履歴から明示的に復元する。

保存対象:

- 日本語原文
- 英語翻訳
- 簡体中国語翻訳
- APIプロバイダ
- モード
- 翻訳スタイル
- 保存日時

履歴UIでは、保存日時、API、モード、日本語原文、英語訳の概要を表示する。

操作:

- 履歴から翻訳結果を復元する
- 履歴を1件削除する
- 履歴を全削除する
- 日本語原文、英語翻訳、簡体中国語翻訳、API、モード、翻訳スタイル、保存日時で検索する
- APIプロバイダで絞り込む
- 翻訳モードで絞り込む

注意:

- 履歴は端末内保存のみで、別端末とは同期しない。
- 患者情報、個人情報、医院名、会社の非公開情報を入力しない運用を前提にする。

## 12.2 お気に入り

講演本番や事前準備で再利用したい翻訳は、お気に入りとして端末内のlocalStorageに固定保存できる。

保存対象は翻訳履歴と同じく、日本語原文、英語翻訳、簡体中国語翻訳、APIプロバイダ、モード、翻訳スタイル、保存日時とする。

操作:

- 現在表示中の翻訳をお気に入りに保存する
- 翻訳履歴からお気に入りに保存する
- お気に入りから翻訳結果を復元する
- お気に入りを1件削除する
- お気に入りを全削除する
- 日本語原文、英語翻訳、簡体中国語翻訳、API、モード、翻訳スタイル、保存日時で検索する
- APIプロバイダで絞り込む
- 翻訳モードで絞り込む

注意:

- お気に入りは履歴とは別に保持する。
- 同じ日本語原文、英語翻訳、簡体中国語翻訳の組み合わせは重複保存しない。
- お気に入りは端末内保存のみで、別端末とは同期しない。

## 13. エラー表示

代表的なエラー:

- マイク拒否
  - マイクの使用が許可されていない旨を表示
- マイク未接続
  - 入力デバイス確認を促す
- APIキー未設定
  - Gemini / OpenAI の該当キー名を表示
- 課金・利用上限

- Gemini 503 high demand
  - 一時混雑として表示し、API切り替えも案内
- 無音
  - 音声未検出として表示

## 15. リアルタイム化方針

完全リアルタイムAPIへ進む前に、まずは疑似リアルタイムを実装する方針が望ましい。

推奨フロー:

```text
録音しっぱなし
↓
1〜2秒ごとに音声を区切る
↓
日本語文字起こしを順次更新
↓
文末・無音・一定文字数で翻訳
↓
英語/中国語を追いかけて更新
```

UI方針:

- 日本語原文
  - ライブ下書き
  - 確定文
- 英語/中国語
  - 翻訳中表示
  - 確定翻訳
- 要確認ポイント
  - 数値、左右、上下顎などを即時抽出

課金対策:

- 無音時は送信しない
- 音声を短く区切りすぎない
- 翻訳は毎秒ではなく文節ごとに実行
- 途中翻訳リクエストはキャンセルまたは破棄
- 講演モードは正確性優先
- Q&Aモードは低遅延優先

将来的な選択肢:

- OpenAI Realtime API
- Gemini Live API

### Phase 4: 講演動画ローカライズ

Keynoteで録画済みの日本語講演MP4を、英語ナレーション付き動画として書き出す。

現在の実装:

- `/video` 画面を追加済み
- MP4ファイルの選択
- ファイル名、容量、長さ、解像度の表示
- ブラウザ内の動画プレビュー
- メイン画面から動画ローカライズ画面への導線
- ffmpeg / ffprobe の利用可否確認
- 選択したMP4を `work/video-localization` へコピーし、16kHz mono WAVを抽出
- 抽出済みWAVをGemini / OpenAIで日本語全文文字起こし
- 文字起こし結果を編集可能な全文テキストとして表示
- 文字起こし全文を既存の翻訳APIで英訳し、編集可能な英訳原稿として表示
- 英訳原稿から英語字幕SRTを生成し、作業フォルダへ保存
- 英訳原稿から標準TTSで1本の英語ナレーション音声を生成
- 生成した英語ナレーション音声を `work/video-localization` 配下へ保存し、画面上で再生
- 元動画の映像トラックと英語ナレーション音声トラックをffmpegで合成し、英語版MP4として書き出し
- 英語版MP4を画面上でプレビュー
- 英語版MP4、英語字幕SRT、日本語文字起こし、英訳原稿、要確認リストを `package` フォルダへまとめる
- 作成済み `package` フォルダをZIPとしてダウンロードできる
- 英語字幕SRTをMP4へ焼き込み、SRT非対応環境向けの字幕焼き込み版MP4を作成できる
- 配布パッケージはSRT同梱版または字幕焼き込み版を選択できる
- 元の日本語MP4は上書きしない

作業フォルダ:

```text
work/video-localization
```

Mac実機検証手順:

```text
docs/video-localization-mac-test.md
```

Windows実機検証手順:

```text
docs/video-localization-windows-test.md
```

注意:

- 作業フォルダはGit管理対象外とする
- 初期MVPではブラウザ経由アップロードのため、まず1GB以下の短い検証動画を対象にする
- 英語版動画は元動画とは別ファイルとして生成する
- 配布用パッケージには元の日本語MP4を含めない
- 初期MVPのZIPは圧縮なしで作成する。MP4は圧縮効果が小さいため、速度と安定性を優先する
- 字幕焼き込み版を選んだ場合、配布用ZIPには焼き込み済みMP4を入れ、SRTファイルは同梱しない
- 英語版では元の日本語音声を完全に差し替える方針
- 初期MVPの英語版MP4は字幕なし。元動画の映像と英語ナレーション音声のみで構成する
- 文字起こしは、まず全文テキストとして表示し、後フェーズでスライド単位・字幕単位へ分割する
- 英訳は、まず全文英訳として表示し、後フェーズで字幕単位へ分割する
- 英語字幕SRTは、初期MVPでは英訳原稿を文単位で分割し、動画長に合わせて初期タイミングを割り当てる
- 英語ナレーションは、まず標準TTSで全文を1本の音声として生成する
- 初期MVPのナレーション原稿は4096文字以内の検証動画を対象にする

MVP入力:

- Mac上で選択した録画済みMP4
- Keynoteの録画機能で作成された講演動画を主対象にする

MVP出力:

- 英語ナレーション入りMP4
- 英語字幕ファイル
- 日本語文字起こし
- 英訳原稿
- 要確認リスト


技術方針:

- Macで使うソフトウェアとして設計する
- 動画処理はローカルのffmpeg利用を基本とする
- Windows検証時は、PATHに加えて `winget` の一般的なffmpeg展開先も確認する
- 文字起こし、翻訳、TTSは既存のGemini / OpenAI連携を活用する
- 動画ファイル全体を常に外部APIへ送るのではなく、必要な音声・テキスト処理だけAPIを使う方針にする
- 将来的なMacアプリ化では Electron または Tauri を検討する

音声方針:

- 初期MVPでは標準TTS音声で英語ナレーションを生成する
- 講演者に似た声の生成は後フェーズでAPI連携する
- 講演者本人の同意がある場合に限り、声質再現または音声クローンAPIを利用する
- 声質再現の音声素材、同意状況、利用範囲は運用上明確に管理する

確認UI:

- 日本語文字起こしを区間ごとに確認、編集できる
- 英訳を区間ごとに確認、編集できる
- 数値、単位、左右、上下顎、術式、禁忌、適応、メーカー名、インプラントシステム名を要確認表示する
- 字幕として使う場合の長さ、改行、表示タイミングを調整できるようにする

現在の準備実装:

- メイン画面に「英語→日本語メモ」パネルを追加済み
- 英語音声を短時間録音し、録音停止後に英語文字起こしを行う
- 英語文字起こしを日本語メモへ翻訳する
- 結果は英語原文と日本語メモとして表示する
- 日本語メモは端末内localStorageへ最大50件保存する
- 現在表示中の英語原文・日本語メモをTXTとしてダウンロードできる
- 「連続メモ」では、15秒 / 30秒 / 60秒の区切り時間を選び、録音中に区切りごとへ英語文字起こしと日本語メモ化を順番に実行する
- 連続メモ録音中は「ここで区切る」ボタンで、話題やQ&Aの切れ目を手動で区切れる
- 手動区切り後は自動区切りタイマーをリセットし、短すぎる次区切りが発生しにくいようにする
- 連続メモの各区切りは、待機中 / 文字起こし中 / 日本語化中 / 完了 / 要再実行 の状態を持つ
- 失敗した区切りは、録音セッション中に保持している音声データから再実行できる
- 連続メモの結果は、区切りごとの英語原文と日本語メモをまとめたTXTとしてダウンロードできる
- 完全同時通訳ではなく、まずは短時間録音単位の疑似リアルタイム化の土台とする
